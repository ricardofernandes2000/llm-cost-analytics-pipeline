# BigQuery Schema

The `llm_analytics` dataset contains the `api_events` table. It stores one row for each fictional LLM API usage event processed by the pipeline.

## Table: `api_events`

| Field | Type | Mode | Description |
| --- | --- | --- | --- |
| `timestamp` | `TIMESTAMP` | `REQUIRED` | UTC time when the API event occurred. |
| `provider` | `STRING` | `REQUIRED` | LLM provider, such as OpenAI, Gemini, or Claude. |
| `model` | `STRING` | `REQUIRED` | Model used for the request. |
| `input_tokens` | `INTEGER` | `REQUIRED` | Number of tokens sent to the model. |
| `output_tokens` | `INTEGER` | `REQUIRED` | Number of tokens generated by the model. |
| `cost_usd` | `FLOAT` | `REQUIRED` | Calculated request cost in US dollars. |
| `latency_ms` | `INTEGER` | `REQUIRED` | Request latency in milliseconds. |
| `status` | `STRING` | `REQUIRED` | Processing result, for example `success` or `error`. |

## Partitioning

The table is partitioned by day using `timestamp`. This keeps time-range queries efficient and helps control BigQuery scan costs as the dataset grows.

## Data flow

1. JSON events are uploaded to the raw Cloud Storage bucket.
2. The ingestion Cloud Function validates and enriches each event.
3. Processed rows are inserted into `llm_analytics.api_events`.
4. The API Function aggregates this table for the React dashboard.
